# 项目交接与新人上手：测试策略、回归套件、待办与陷阱

项目交接精华 + 新人上手路径。权威源 `docs/21-项目交接说明.md`（315 行，21 小节 + 陷阱清单 + 待办表）。

## 新人上手路径（从“先只读”到“动手”）

1. **先只读**：`pnpm run typecheck` → `pnpm test`（92 套件）。确认基线绿后才动任何东西。
2. **读懂两条线**：`docs/15-内容录入流水线.md` → `docs/20-存量优化流水线方案.md`（§4 是浓缩版，已迁 `knowledge/` 下存量优化页）。
3. **观察而不写**：`kg-optimize scan --scope 数据链路层`，再用 `dedup --only-title` 看模型怎么找重复。
4. **动手前先 dry-run**：任何 `--apply` / `apply` 前先跑 dry-run；写库前备份主库；记下批次号以便回滚。
5. **改 prompt 必 bump 版本**：`EXTRACT_PROMPT_VERSION` / `DEDUP_PROMPT_VERSION` / `SKELETON_RULE_VERSION`，否则缓存会让改动看起来「没生效」。
6. **加新动作要登记两处**：`DraftNodeAction` 与 `asAction`，并补一条变异点。
7. **写完按 §7 跑回归**：全量回归 + 变异；只跑单测不算验证过链路。

**原则**：有任何与本文不符的实测结果，**以实测为准并更新本文**——文档的价值在于把「当时以为对、后来被数据推翻」的结论留在纸上。

## 测试策略：验收就是「变异 + 回归」

- **变异测试证明脚本不是空转**。每个新功能都要做「该红的红、不该红的不红」：把实现改坏，看断言是否变红；还原，看是否回绿。只跑绿不跑红，等于不知道测试在不在测东西。
- **单测绿 ≠ 链路通**。回归与变异要**串行**；变异点带换行先归一 CRLF；**绝不读全文 → 正则替换 → 整体写回**（曾写空过文件）。
- **验收原则：不写硬编码的全局总数**。知识点导入/去重会改变节点总数，写死数字的话每跑一次不同输入就红一片。正确做法：用真库跑之前先算实际数，再逐项断言「相对差值」。

## 工具链踩坑（§8，与 codeb 工具链页互补，未重复部分）

- 解析缓存按仓库根算；`--text-dir` 空值 `resolve('')` = 项目根 → 要 filter 掉 `node_modules` / `.git` / `.cache` / `dist`。
- `--merge-into` 不加就是「77 页变 1 页」且无报错。
- `run({dryRun})` 曾无条件 `batches.create` → 空批次写「合并 2」却无 item。
- `bind-containers.ts`：`items` 与 `ops[].item` 是两份对象，只改一边 → apply 报「父占位键没有对应创建操作」并跳过整棵子树。
- `batch` 的 `$ref` 只解析顶层 REF_FIELDS，**不进 `relate_knowledge_ids` 数组** → 建树与挂题分两个 batch。
- 新 LLM 调用点先确认走 `opts.chat`（`extractSectionGuide` 曾硬调 `chat()` 绕过注入）。
- 日志必须有「向量化 N/N」后的「判定 k/N」；embedding 静默降级 → 计划全假「新建」。
- 重名四分支判据（已迁 `knowledge/` 下存量优化页）：标题字面相同 ≠ 必合并（`中继器` / `中继器（Repeater）` 是 variant）；「标题包含」不是扁平化判据（`中值定理` 会塌进子节点，拆掉章级主题）。
