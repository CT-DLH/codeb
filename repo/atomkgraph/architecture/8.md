# 核心数据模型：8 个实体表与已确认的设计原则

核心数据模型。权威源 `docs/04-数据模型.md`（156 行，8 个表 + 一批已确认的设计原则）。

## 原子知识点定义（门槛）

可独立讲解、可独立**检验**的最小完整知识单元。「检验」不限于做题，也包括复述、解释、操作演示、案例分析——兼容文理各学科。

粒度判据：能独立讲解 ✓ / 能独立检验 ✓ / 边界明确 ✓；❌ 塞了两个并列内容 → 拆；❌ 拆完只剩半句话、无法检验 → 合并。参考长度 80–400 字（非硬指标）；同一父节点下子节点信息量偏差不超过 2 倍；子节点少于 2 个时合并回父节点。

**层级 = 包含关系，不预设深度**。分层原子化（已确认）：原子粒度随下钻层级而定。高层只呈现主干（运算 → 加法→乘法→乘方），下钻到某节点后才展开细节（选中「加法」才显示进位/不进位加法）。主线链上的节点保持主干粒度；粒度标准只约束叶子节点。

**知识形态**（`knowledge_type`）：mechanism / derivation / fact / argument / skill。首批支持计算机（mechanism）、数学（derivation）、一门文科（argument）；**技能型暂不纳入**（系统面向文本化知识，不含乐器/口语/体育等操作性技能）。

## 8 个实体表

| 表 | 主要字段 | 说明 |
|---|---|---|
| `knowledge` | knowledge_id, title, content, parent_id, tag_ids[], knowledge_type, weight, difficulty, sort_order, review_status, edit_count, content_hash, deleted_at, pos_x, pos_y, pos_pinned, ease_factor, interval_days, last_review_at, repetitions, source, refs[], viz[], create/update_time | 知识库。difficulty 越大越简单（0.9=送分题, 0.3=难题）。content_hash 用于导入去重。deleted_at 软删除。`mastery`/`status`**不存储**（派生）。refs/visualizations**不并入 content**（改文献不动 content_hash；viz 是自包含 HTML，每节点 ≤5 条、单条 ≤256 KB，由 iframe srcdoc 承载） |
| `question` | question_id, type, content, answer, analysis, difficulty, relate_knowledge_ids[], review_status, content_hash, deleted_at, source | 题库，与知识库独立，通过 relate_knowledge_ids 多对多映射；可挂单个/多个/集合/跨层级节点 |
| `tag` | tag_id, name, parent_tag_id, description | 分层标签树（领域、章节、难度、考点、时效性），可跨分支多选 |
| `record` | record_id, type(答题/学习时长/提问/复习), target_id, result, duration, timestamp | 学习记录库 |
| `review_queue` | 知识点集合、到期时间、重要性、复习次数、上次复习时间 | 基于遗忘曲线生成的复习计划 |
| `relation` | relation_id, source_id, target_id, relation_type(prerequisite/related/confusable), weight, source, review_status, create_time | 前置为有向边，相关/易混为无向边（存储按 ID 升序归一） |
| `knowledge_revision` | revision_id, knowledge_id, snapshot, change_type, operator, create_time | 知识点版本历史（创建/AI 补充/人工修正/对话沉淀/拆分/合并；operator user/ai） |
| `question_revision` | revision_id, question_id, snapshot(完整题目 JSON), change_note, create_time | 题目版本历史（与 knowledge_revision 逐字同构，**不复用**那张表——外键指向不同且索引/查询模式不一致） |

## 已确认的设计原则（已落库，不是猜测）

1. **mastery / status 不作为存储字段**：由 SM-2 参数 + 答题记录 + 配置阈值**实时派生**，避免全库后台重算。
2. **前置是展示而非门禁**：`prerequisite` 边只用于展示先后顺序、推荐学习路径、图谱链式排列，**不阻塞**学习/答题/推进度。系统不设锁定/解锁。
3. **主线与支线由图结构客观判断**：某父节点下的连通子图内，取最长前置链为主线，其余较短分叉为支线。**无需新增字段**，复用现有 prerequisite 边推导；无明确推进关系的分支不强套链。
4. **主线链上的前置不逐级原子化**：链本身承担推进语义；更细拆分放在下钻后展开。
5. **易混信息归属主节点**：如「加减法易混」放在主线节点（加法）中即可（学习顺序「由加法再到减法」）。
6. **question_revision 写入时机**：每次 `QuestionRepository.update()` 前落快照；rollback 亦先存当前状态（回滚本身可再回滚）；空 patch 不留版本；删除题目时连同版本历史一并清理。批量侧由 `akg_batch` 的 `question_update` op 走同一写路径，不分叉。
7. **为什么不复用 `knowledge_revision` 给题库**：外键指向 `knowledge(knowledge_id)`，混用直接破坏引用完整性；且索引与查询模式按 knowledge_id 优化，题库侧对不上。
