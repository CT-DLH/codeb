## 核心判据（设计意图而非结论）

**重名四分支（只有一支会动库）**：

- **T0 假重名**：标题互不为前缀（`titleGroupKind === 'distinct'`），如 `含 √(x²+a²) 的积分` / `含 √(x²−a²) 的积分` / `含 √(a²−x²) 的积分` 三个不同公式族——`observe`，一个字都不改。**「标题是否完全相同」不能做判据**（`中继器` 与 `中继器（Repeater）` 不同，是 variant，要往下走）。
- **T1 同父同名**：相似 ≥0.95 → `merge(contentPolicy='longest')`，tier auto；0.6–0.95 → `merge(contentPolicy='union')`，tier review；<0.6 → 不合并，`observe` + `blocked='needs-manual-title'`。**同父下「异义」两份正文相似 0%，合并等于拼两篇不相关的东西**（实测命中过）。
- **T2 跨父同名**：默认不动，只写进报告 `observe`。`本章小结及疑难点` ×3 额外打「章级通用标题，禁止合并」警告。
- **T3 双挂载**：跨父 + 正文 `content_hash` 完全相同。`pickKeeper` 选主位置（子树规模 > 正文长度 > 挂载题数 > 建得早），被吸收的子树 merge 进 keeper，在失去父位置的上级与 keeper 间建 `relation(related)`。**本版不自动建关系边，写进 `warnings` 提醒人工补**。

**扁平化命名冗余（不是「标题包含」）**：

旧判据「标题包含」被废掉——它把「命名冗余」和「上位主题与分支」混成一类。`中值定理`(1362 字) 塌进 `多中值点问题` 会拆掉章级主题。新判据 `namingVariant()`：**剥掉括注（中英对照、补充说明）后完全相同**，或只多一个「概述/简介/Overview」这类通用词。

| 实测 | 动作 | tier | 例子 |
|---|---|---|---|
| 剥括注后相同，容器无正文 | 子上提、软删容器 | auto | —— |
| 剥括注后相同，容器是导读/一句话铺垫 | 容器正文并入子节点开头 | review | `缩短命中时间 → 缩短命中时间（避免地址转换）` |
| 剥括注后相同，容器是同一主题的另一版正文 | **不做**，标 `needs-content-merge` | observe | `中继器 → 中继器（Repeater）` |
| 子标题带实质限定词 | **不做**，那是上位主题与分支 | 不提案 | `泰勒公式 → 泰勒公式的一般形式` |
| 标题无关 | 不做 | 不提案 | —— |

## graphFingerprint（硬性安全要求）

提案可能放几天再执行，期间增量流水线可能落库。指纹覆盖 **节点 id + 父 + 标题 + 正文 hash**，任何一项变化都拒绝 apply。**只改正文不改标题也必须让指纹失效**——否则「正文已更新」的提案会拿旧指纹过校验。排序：`auto → review → manual → observe`，同档按 id 稳定排序，保证同一份库两次 propose 的 `planHash` 一致（`--confirm <planHash>` 用于审阅稿校验）。

## 回滚口径（代码里有实现，测试里有变异）

`apply` 一律禁止：删除有挂载题目的节点（改挂到 keeper 后才行）、合并含图片节点时丢 `![...](/api/assets/...)` 引用（按 URL 去重后并集）、跨一批次同时改父和改标题（回滚会错位）。

`collapse` 回滚三趟：①取消容器软删 → ②还原子节点 `parent_id` 与正文（含 `edit_count`/`content_hash` 整行裸写）→ ③把挂载题与关系边从子节点搬回容器。任一环缺失会留下「正文回不去」或「题目指向错节点」。`test-optimize-plan.ts` 对这三件事各有独立断言，`mutate-optimize-plan.mjs` 各有变异点。

记账：一条 item 装下整件事（容器快照 + 子节点原貌 + 边），回滚三趟：取消软删 → 还原子节点父位置与正文 → 边搬回。

## 与增量流水线的耦合点（关键）

- **改名会让增量重建同名节点**：增量的三层结构匹配按标题键对齐，节点改名后旧名不再命中，下次录入同一材料会新建一份。**解决方式**：新增 `knowledge_alias` 表，rename/reparent 时把旧标题写进去，`collectExistingNodes` 建索引时同时收 alias 键。**新表必须走 `migrate()` 的 `CREATE TABLE IF NOT EXISTS`，不能塞进 `SCHEMA_SQL`**（老库会因表不存在直接报错，与历史踩坑一致）。
- **索引漂移的根因在增量侧**：110 条 stale 全部集中在最近录入的数据链路层，说明批量脚本绕过 `autoIndex` 是系统性的。优化侧只能事后补，根治要在写入层统一重建。
- 增量留下的 4 条有意保留的重名 create（`plan-final-noconflict.json` 里带图和内容的那些），由本流水线的 T1/T2 分支接手，不在增量侧再处理。
