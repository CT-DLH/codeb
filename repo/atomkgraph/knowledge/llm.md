# 知识点查重/归并流水线：召回、LLM 判定与阈值

录入新知识点时，如何与库里已有的几百个节点比对，决定「新增 / 归并 / 挂为子节点」。这是**知识点侧**的流水线（内容/题目侧见 `knowledge/l0-l3`）。权威源 `docs/14-知识点流水线.md`。

## 链路：L0 解析 → L1 切分 → L2 抽取 → L3 去重/落库

前三层和内容录入共用骨架，差别全在 **L3**：新知识点不是直接落库，而是先**召回候选**、再由 **LLM 判定关系**、最后**归并或新增**。

## 去重判定（LLM 裁决）

召回若干候选后，LLM 对每个候选判三选一：

- **merge（归并）**：同一概念不同措辞 → 并入已有节点，新表述存为别名。
- **add_child（挂子节点）**：是已有节点的细分/特例 → 挂为其子节点。
- **unrelated（无关）**：确实新概念 → 新增顶层节点。

判定结果不是只看 LLM——**向量相似度过高时强制归并**（见阈值），相似度极低时跳过判定直接新增，省 LLM 调用。

## 召回（两路）

- **向量检索**：`text-embedding-3-small`（1536 维）对已有节点做相似度召回。这是主路。
- **关键词补召回**：兜住向量模型对专有名词/缩写不敏感的情况。

**两个阈值**：约 0.87 以上视为「几乎肯定是同一节点」（高置信归并）；约 0.80 以下视为「低召回」（可能是新概念，但仍送 LLM 判一遍以防漏）。中间区间最需要 LLM 介入。

## 验收原则（本项目反复强调）

**不写硬编码的全局总数**。归并/新增会改变节点总数，写死数字的话每跑一次不同输入就红一片。正确做法：**用真库跑之前先算实际数，再逐项断言「相对差值」**——比如「这次导入后顶层节点数应 +1（新增）、某节点别名数应 +1（归并）」。

## 与内容录入的分工

- **知识点查重/归并**：解决「这个概念库里是不是已经有了」。走本页链路。
- **内容/题目录入**：解决「把一份题库文档结构化落库」。走 `knowledge/l0-l3`。
- 两者在 R42 统一录入里合到同一套 plan（`planUnifiedIngest`），一次审阅一次应用——但**去重判定只在知识点侧触发**，题目侧靠 `duplicateWithinPaper`（同卷去重）而非向量检索。
