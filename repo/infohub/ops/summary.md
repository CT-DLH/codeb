# 导师简介的内容口径

`info_mentor` 的 `summary` 是用来在**列表页的一行里**回答「这个人是谁、做什么方向」的。它会被复用到列表、详情页、以及 LLM 上下文里，所以稳定比个性化重要。

引擎与闸的机制见 `infohub/ops/pipelines`；这一页只记**内容该怎么写**——那部分不在代码里，也不能靠调参数得到。

## 四槽结构

固定四段，顺序不变，缺哪段就跳过（不留空位、不补占位）：

```
① 职务/身份   ② 所属单位   ③ 学术任职或代表性工作   ④ 研究方向：方向A、方向B、方向C
```

- 前三个槽用顿号或逗号连成一句话，**不写编号**（`①` 只出现在提示词里当约束，不落到卡片上）。
- 第四槽必须以 `研究方向：` 开头。冒号**只允许出现这一次**——早期版本用 `；` 和 `,` 混排，同一批输出里出现了三种冒号风格，列表页看起来像三种不同模板拼出来的。
- 研究方向给 3~5 个，用顿号分隔。少于 3 个通常是材料里只有一个泛词；多于 5 个说明把论文标题当方向抄了。

一句话读起来应该是「某某，某单位某职务，某学术任职，研究方向：A、B、C」。长度落在 40~120 汉字。**注意：`pipelines/mentor-summary-unify.json` 当前并没有配 `max_output_chars`**（2026-11 核对），长度上限只由提示词的「20~120 字」约束，没有写盘前的硬闸；配置也没有 `require_cjk` / `strip_leading_title` / `concurrency`。这些键在 `batch_llm.ts` 里都支持，只是这份配置没启用。

## 六条内容红线

1. **职称只在材料里有时才写**。材料说「在某校任教」，不能推出「副教授」。这是 `grounding.terms` 拦的第一类错——也是实测里最常被模型补的一个词。
2. **英文职称保持英文**。材料写 `Associate Professor` 就写 `Associate Professor`，不要译成「副教授」。译了以后读者无法回查，而且和同批中文材料里的「副教授」混在一起分不清哪个是原文。
3. **研究方向只能来自材料或 `ext.research`**，不自造、不合并近义词、不把一个大方向拆成三个子方向充数。
4. **履历不是现职**。「曾任 XX 大学讲师」不进前三个槽——读者要的是他现在是谁。真有任职价值，放第三槽并标明时间关系。
5. **不列论文**。不写「发表论文 N 篇」、不点论文标题。论文自有 `科研论文` 小节与 `mentor:papers` 生成的综述，简介里重复一遍只会让两个地方的数字对不上。
6. **没有材料就不写**。全空的卡写「研究方向未在主页披露」——**这是唯一允许的占位**，它明确告诉读者「不是我们漏了，是源站没有」，比编一句漂亮话诚实，也让后续补采能一眼看出哪些卡还在等材料。

## 姓名不进简介

开头不要写人名。列表页姓名是单独一列，详情页标题也是姓名，简介再写一遍就是同一屏出现三次。

这条**写进提示词也不够**：实测提示词明确说了「开头不要写姓名」，仍有一成多的输出照旧以姓名开头。所以引擎侧配了 `strip_leading_title` 兜底——它的实现有个必须记住的顺序约束，见 `infohub/ops/pipelines`（剥姓名的动作必须排在「与现值比较」**之前**，否则每次重跑都判成有改动，幂等与统计一起失真）。

## 「研究方向未在主页披露」是答案，不是缺陷

主页抓回来的「个人简介」有一批是占位文案（一句「主页未提供个人简介栏目」、或者只有一个网址）。`source_min_chars` 拦住它们、不请求模型，最终落成上面那句占位。

**不要为了消灭这个占位去放宽闸**。它标记的是「源站确实没有」，是采集待办清单的一部分；把它换成一句模型编的方向描述，等于用一个假事实换掉一条真实的待办。

同理，材料太薄但非空时（比如只有一行「主要研究兴趣」），写出来的可能只有第三、四槽——允许，不要为了四槽齐全去补前两槽。

## 与 `mentor:papers` 的分工

| 内容 | 归属 |
| :-- | :-- |
| 一句话身份 + 研究方向 | `summary`（本页） |
| 论文脉络、3~6 条研究主线、代表作 | `科研论文` 小节（`npm run mentor:papers`） |

简介里出现论文统计或代表作标题，就是两套口径在打架。`mentor:papers` 的逐字校验只保证标题真在库里，管不到简介那边——简介里的论文名没有人校验。

## 写之前先看源字段干不干净

`ext.research` 是主要材料来源之一，但它有一部分是**论文标题的连写残片**（含拼写错误，如把 Video 写成 Videso）。模型会忠实抄进去，接地闸也放行——因为每个字确实在材料里。

所以遇到「输出荒谬但过了闸」，去看源字段，不要调阈值。判据与处置见 `infohub/ops/pipelines` 的「闸的盲区」一节。

## 当前配置与本节口径的偏差（2026-11 核对）

本页记的是**内容目标**，`pipelines/mentor-summary-unify.json` 是**实际执行的约束**。两者目前不一致，
按本页写提示词的人会以为约束已经落地。逐条列出，改配置时先看这里：

| 本节口径 | 配置实况 |
| :-- | :-- |
| 四槽结构、`研究方向：` 冒号只许出现一次 | 提示词只要求「2~3 句中文，20~120 字」，**没有四槽结构**、也没有冒号规则 |
| 长度 40~120 汉字，`max_output_chars: 180` 兜底 | **没有 `max_output_chars` 键**；上限只靠提示词里的「20~120 字」 |
| 研究方向只能来自材料或 `ext.research` | `grounding.corpus_fields` 只有 `["ext.dept"]`，**`ext.research` 不在白名单**（比本节更严：`ext.research` 只能经正文材料进入） |
| 材料不足不请求模型 | 有 `source_min_chars: 30` 与 `min_output_chars: 20` ✅ |
| 接地阈值 | `grounding.min_cjk_coverage: 0.45`，不是别处文档写的 0.5 |
| 材料范围 | `source_sections: ["个人简介", "研究方向"]`，**只两节**（不含「研究与工作经历」「专业资质与学术兼职」） |

`grounding.terms` 的 12 项是：教授 / 副教授 / 助理教授 / 讲师 / 博士生导师 / 硕士生导师 /
国家级 / 省部级 / 院士 / 特聘 / 长江学者 / 杰青 / 优青。

这份配置**没有 `save_mode`**，引擎默认 `jsonl`，所以产出是 `inbox/mentor-summary-unify.jsonl`，
**落盘还要过一遍 `card_import` 预演**，不是直接改卡。端到端流程见
`infohub/collector/crawl-db-jsonl-llm`。
